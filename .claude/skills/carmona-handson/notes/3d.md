# 3d · Security · Authorization

Source: https://insper.github.io/platform/2026.2/hands-on/3/authorization/

- `gateway-service`: `spring-cloud-starter-gateway-server-webflux` + webflux. Reference uses a `GlobalFilter` + `RouterValidator` ("METHOD /path" whitelist), calls `/auth/solve` per request via `WebClient`, then adds `id-account` and `Authorization: Bearer` downstream.
- Routes in yaml under `spring.cloud.gateway.server.webflux.routes` (`Path=/accounts/**` → `http://account:8080`, `Path=/auth/**` → `http://auth:8080`); `globalcors` from env.
- Compose: db → account → auth → gateway; only gateway publishes 8080.

## Carmona overrides

- Spring Security resource server (reactive) with `jwk-set-uri: http://auth:8080/auth/jwks` and issuer check; open routes via `pathMatchers(POST, "/auth/login", "/auth/register").permitAll()`.
- A global filter always strips inbound `id-account`, then sets it from `jwt.sub` on authenticated requests. No `Authorization` forwarding needed downstream.
- Routes are explicit, not `/accounts/**`: only `GET|DELETE /accounts/{id}` reach account, and account-service returns 403 unless `id-account` equals `{id}`. `GET /accounts` (list) and `POST /accounts[/login]` stay internal.
- Token-bucket rate limit per account id (or client IP on open routes) at the gateway; httpclient connect/response timeouts.
- No reference defaults (`DB_PASSWORD:-devpass`), no published DB port, pinned image digests.
