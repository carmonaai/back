# Later-phase platform conventions

From the Insper reference, with Carmona overrides applied. Follow it when each piece arrives — **observability and the compose harness are built** ([observability.md](observability.md), the last bullet below); the rest is not.

- **Edge**: Caddy, the only published service (decision D-26; HOST-08; **not built**: the harness publishes the gateway on `127.0.0.1:8080` only). The design (HOST-08): Caddy 2.11.7 with `request_body { max_size 5MB }` (the gateway enforces its own 4 MB), `reverse_proxy gateway:8080` with `flush_interval -1` so tokens stream, a `response_header_timeout` of 12 minutes (above the gateway's 660 s drain), a health check on the gateway's readiness at port 8081, and only the public paths forwarded (`/v1/*`, `/auth/*`, `/accounts/*`, `/organizations/*`, `/billing/*`, `/usage/*`); everything else, `/actuator` included, is a 404. The server `write` timeout is never set (it caps whole streams). `X-Forwarded-For` from an untrusted client is overwritten, and the `%2F` in a model id's path must reach the gateway unchanged (SDKs send it that way; to be proven by the edge checks). The gateway believes the forwarded address from the edge only: `carmona.gateway.trusted-proxies` is the edge container's fixed address (empty by default; set only after port 8080 is no longer published). With several gateway replicas the gateway balances each request across the replicas of an upstream itself (it opens a connection per request and re-resolves DNS every 5 s), which is why an orchestrator that removes unready replicas from DNS is what makes readiness count. Replicas come from compose `deploy.replicas` or K8s; the gateway keeps its shared state in Valkey.
- **Cache (Valkey 9.0.6, BSD; the reference says Redis)**: the services use the Redis client directly (`spring-boot-starter-data-redis`, Lua scripts), not Spring Cache: the gateway's key lookup and flood-brake buckets, billing's `no_credit` flags, inference-service's rate buckets, slot leases and usage stream. Every key has a TTL or is rebuilt (the usage stream lives until stored, and Valkey keeps an append-only file). Cached personal data carries a TTL and is evicted on erasure; the one personal value is the client address in `rl:gw:anonymous:<ip>`, which expires after 120 s.
- **Messaging (Kafka)**: `spring-kafka`; producer `acks=all`, `enable.idempotence=true`, JSON values, string keys. Topics `<domain>-events` + `<domain>-events-dlq`; consumers idempotent with manual commit and one group per consumer. Use KRaft (the reference compose uses ZooKeeper); create topics explicitly outside dev. Events carry ids, never personal data.
- **Compose stack (the harness, 2026-10-09 and 2026-10-15)**: `docker/compose.yaml` runs the eight services, Postgres, Valkey, Mailpit, Prometheus, Grafana and a **simulated engine** (`llm-d-inference-sim` v0.11.4 patched to notice a hang-up and report usage on every chunk: a local build, `bash docker/sim/build.sh`, `pull_policy: never`; ADR 0002); there is no CPU engine. `docker/compose.gpu.yaml` is the overlay for vLLM on the laptop GPU, `docker/compose.minio.yaml` adds the S3-compatible bucket batch-service needs, and the profile `fleet` (`docker/fleet.env`) runs several engine, inference and gateway replicas behind an nginx stand-in for the replica picker. `tools` (curl, bash, python3; non-root, read-only) is the script host on the network: `smoke.sh`, the benches and the operator calls to internal endpoints run from it, with `-H @/run/secrets/internal_token`. Create the shared secret before the first `up` with `bash docker/init-secrets.sh` (BE-24: billing, organization, account and auth do not start without it; the gateway never gets it). Every container a step touches is non-root with dropped capabilities where it needs none, and the gateway publishes `127.0.0.1:8080` only. Secrets stay out of the repo: `.env.example` lists every name, and a run supplies the values it needs. The checks: `smoke.sh` (end to end, with the canary sweep and the S15 internal-secret checks), `bench.sh`, `batch-bench.sh`, `revenue-check.sh`, `check-prometheus.sh`, `check-fleet-targets.sh`, `check-sim-disconnect.sh`. Compose has one `internal` network; the three-network split (`edge`, `backend`, `observability`) is HOST-06's. No long-running service has a restart policy, and the gateway has no `stop_grace_period: 720s` yet.
- **Observability**: logs as JSON on stdout with `trace_id`/`span_id`; traces via the OpenTelemetry Java agent in the image (`OTEL_SERVICE_NAME`, `OTEL_EXPORTER_OTLP_ENDPOINT`, `OTEL_PROPAGATORS=tracecontext,baggage`, sampler `parentbased_traceidratio` 0.1 in prod) — **not built**; metrics via `micrometer-registry-prometheus`, scraped on the management port every 15 s by Prometheus and drawn by Grafana (RED per service, one SLO dashboard), provisioned from `docker/` — built 2026-10-05, SLIs/SLOs and the gaps in [observability.md](observability.md); no Alertmanager yet, so alert rules and their firing state live in Prometheus and Grafana.
- **Kubernetes**: Deployment + ClusterIP Service + ConfigMap + Secret per component; requests/limits on every container (reference baseline 256Mi/250m requests, 512Mi/500m limits); liveness/readiness probes; HPA; secrets from a secret manager (K8s Secrets are only base64).
- **CI/CD**: reference uses Jenkins (declarative, `mvn -B clean install`, buildx push to Docker Hub, `withCredentials`). The tool is a pending decision. Run tests in CI (the reference passes `-DskipTests`) and tag images with the commit SHA.
