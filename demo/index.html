Carmona: the whole workflow

This page plays the console, on localhost:3000 (the origin the stack trusts). It talks only to the gateway, the way a customer would. Three /dev helpers stand in for things a customer can't do: read the email Mailpit caught, add prepaid credit, and show a balance.

How it's built

browser / OpenAI SDK
   │  HTTPS
   ▼
gateway ── checks the JWT or API key · refuses foreign Origins · rate brake · request id · access log
   ├─ /auth, /accounts        ─► auth-service ─► account-service ─► email (Mailpit locally)
   ├─ /organizations, keys    ─► organization-service, auth-service
   ├─ /v1/chat/completions    ─► inference-service ─► engine: llama.cpp (CPU) or vLLM (GPU)
   │                                 └─ usage events ─► usage-service ◄─ billing-service ─► "no credit" flag
   └─ /v1/files, /v1/batches  ─► batch-service ─► inference-service (lowest priority)

  • One Java service per job, each with its own schema. Services call each other through shared Feign interfaces; only the gateway is public.
  • The gateway decides who you are. Services trust the identity headers it sets, and only those.
  • No database on the chat path: Valkey and in-memory counters only. Money moves later, from usage windows.
  • Privacy by design: logs and usage hold ids and counts, never prompts, answers, emails or keys.
